# Проверка CRM перед публикацией

Проверка выполнена 28 сентября 2026 года. Исходная версия: `abb60b7` (PR #41), плюс исправления в этой ветке. Область: исходники приложения, маршруты CRM, HTML/JavaScript, настройки, зависимости текущего окружения и развёртывание. Продуктивный сервер, его ОС, SSH, firewall, DNS и содержимое базы не проверялись; доступа к ним нет.

## Найдено и исправлено

| Проблема | Исправление | Проверка |
|---|---|---|
| CIDR/localhost позволяли запуск CRM без пароля. За reverse proxy все запросы могут приходить с localhost. | Логин и пароль обязательны для всей включённой CRM, независимо от сети; публичный режим разрешает только bind на 127.0.0.1. | Без авторизации все маршруты, включая API и healthz, возвращают 401. |
| Артикул вставлялся в inline JavaScript кнопок. `encodeURIComponent` оставляет апостроф, который мог закрыть JS-строку. | Inline-обработчики удалены; данные передаются в экранированных HTML-атрибутах, действия вызываются через обработчики событий. | Артикул с кавычками и HTML не создаёт обработчик или тег. CSP разрешает только хеши штатного скрипта и стилей. |
| Не было явной CSRF-защиты, JSON принимался без проверки Content-Type. | Для изменений обязательны токен из авторизованного `/api/session` и application/json. Проверяются Origin и Sec-Fetch-Site. | Все три маршрута изменения отклоняют чужой Origin, отсутствующий/неверный токен и cross-site запросы. Штатное редактирование работает. |
| Отсутствовали ограничение попыток входа, запрет встраивания и политика кеширования для всех ответов. | 10 неверных авторизаций в минуту на адрес, затем 429; CSP/frame-ancestors, X-Frame-Options, nosniff, no-referrer, no-store. | Проверены лимит, окончание блокировки и заголовки ответов. |
| Допускались старые версии aiohttp, большие/сжатые тела запросов и нецелочисленные количества. | aiohttp >=3.14.3; запрет сжатых запросов, лимит 16 KiB; строгие целые значения в допустимом диапазоне. | Проверены 413/415/400 и отсутствие записи при ошибках. |
| deploy.sh не проверял готовность CRM и не готовил HTTPS. | Режим Caddy с проверкой домена, конфигурации, обязательного пароля и healthcheck; localhost; отдельный systemd drop-in; восстановление кода/конфигурации при ошибках. | Проверены генерация и валидация файлов, Bash-синтаксис; Caddy 2.11.4 принял конфигурацию. Реальная установка APT/systemd на сервере ещё не выполнялась. |
| Автообновление из CRM потребовало бы привилегированного запуска. | CRM видит только опубликованные релизы с явным `CRM-Update: self-service`, совпадающие с `main` и доступные fast-forward. Изменения известных файлов конфигурации сервера блокируют кнопку. Обновление запускает фиксированная root-owned systemd-служба по запрос-файлу в каталоге data, без sudo и без снятия NoNewPrivileges=true. Маршрут защищён Basic Auth и CSRF. | Проверены пропуск релизов без маркера, меняющих конфигурацию, отличающихся от `main` и не fast-forward; тест проверяет создание фиксированного файла-запроса и конфигурацию path-unit. Реальный systemd-путь проверяется обычным `deploy.sh` на сервере. |

## Проверка скрытого доступа

В проверенных исходниках не обнаружены скрытые аккаунты, отдельные маршруты обхода авторизации, функции запуска произвольных команд из HTTP-запросов, динамическое выполнение переданного кода или посторонние адреса выгрузки данных. Веб-сервер не раздаёт каталог проекта: `.env`, `.git`, SQLite и исходники недоступны как статические файлы. Запросы SQL используют параметры для пользовательских значений. Telegram-команды, меняющие данные, проверяют список разрешённых chat_id.

Это результат проверки доступного кода, а не доказательство отсутствия любых закладок: содержимое рабочего сервера и бинарные зависимости целиком не исследовались.

## Зависимости

`pip-audit 2.10.1` проверил все 10 пакетов из зафиксированного вывода `pip freeze` локального окружения. Известных уязвимостей на дату проверки не найдено. В составе: aiohttp 3.14.3, python-dotenv 1.2.3, aiohappyeyeballs 2.7.1, aiosignal 1.4.0, attrs 26.1.0, frozenlist 1.8.0, idna 3.20, multidict 6.9.1, propcache 0.5.4, yarl 1.25.1. CI повторяет аудит установленных версий; deploy обновляет также транзитивные зависимости. Результат базы уязвимостей не исключает ещё не опубликованных проблем.

## Границы публичной установки

- Поддерживаемый автоматический установщик: Debian/Ubuntu, systemd, Caddy из официального репозитория. Домен и доступ TCP 80/443 обеспечиваются отдельно.
- Пароль хранится в `.env` и передаётся браузером через HTTPS Basic Auth. Используется один административный аккаунт; MFA и пользовательские роли не реализованы.
- Ограничение попыток входа действует в памяти процесса и сбрасывается при перезапуске. От распределённого DDoS оно не защищает.
- Приложение доверяет специальному адресу клиента только от локального Caddy в публичном режиме. Другие локальные процессы и root входят в доверенную зону сервера.
- Кнопка обновления выполняет root-деплой кода из доверенного `main`. Доступ к паролю CRM даёт право запустить этот фиксированный деплой; новые релизы должны быть явно отмечены как self-service только после проверки требований к `.env` и серверу.
- До первого обновления нужно заполнить CRM_USER/CRM_PASSWORD. При отсутствии домена публикация откладывается; CRM доступна локально с авторизацией или через SSH-туннель.
- После настройки требуется внешняя проверка сертификата, авторизации, закрытого порта 8080 и всех трёх вкладок на реальном сервере.

Источники: [установка Caddy](https://caddyserver.com/docs/install), [reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [бюллетени aiohttp](https://github.com/aio-libs/aiohttp/security/advisories).

### Дополнение: нестандартный HTTPS-порт и Selectel DNS

- Public URL допускает явный порт, но Host/Origin по-прежнему сравниваются полностью;
  проверены запросы на 4443, отклонение другого порта и легитимное изменение остатков.
- DNS-01 отключает HTTP/TLS-ALPN challenge и автоматический HTTP redirect listener.
- Сервисные учётные данные Selectel находятся вне репозитория, root-only; Caddy
  получает их через EnvironmentFile без печати окружения и без shell `source`.
- Caddy/xcaddy/DNS-модуль зафиксированы; Go скачивается по HTTPS с проверкой SHA256
  официального манифеста. Сборка отдельная от APT, обновляется явно через установщик.
- Проверены 193 Python-теста, тесты UI, синтаксис shell, сборка Caddy и его валидация
  DNS-only конфигурации. Реальный выпуск/продление сертификата и запуск systemd
  требуют проверки на сервере с рабочими учётными данными DNS.
